# CPVTS Deployment Guide

Planned topology:

```text
Web (static SPA)  → Vercel
API (Node/Express) → Render
Database           → Supabase PostgreSQL
Android            → WebView APK of the same web app (later phase)
```

Every piece is replaceable: the web app is a static bundle, the API is a
standard Node.js process (or Docker image) configured by environment
variables, and the database is reached through a standard PostgreSQL URL.

Deploy in this order: **database → API → web → update API CORS**.

---

## Supabase (PostgreSQL)

1. Create a project. Pick a region close to users and to the API
   (e.g. Mumbai `ap-south-1` with Render Singapore). Save the database password.
2. **Connection strings** (dashboard → **Connect**):

   | Mode               | Port | Use                                               |
   | ------------------ | ---- | ------------------------------------------------- |
   | Session pooler     | 5432 | Recommended for the API and for migrations (IPv4) |
   | Transaction pooler | 6543 | Optional for `DATABASE_URL`; never for migrations |
   | Direct connection  | 5432 | IPv6-only unless the IPv4 add-on is enabled       |

   Render does not support outbound IPv6, so use the pooler host
   (`aws-0-<region>.pooler.supabase.com`) with the username `postgres.<project-ref>`.

3. **SSL.** The runtime driver (node-postgres) and the Prisma CLI read SSL
   parameters differently, which is why two URLs exist:

   ```dotenv
   DATABASE_URL=postgresql://postgres.<ref>:<password>@aws-0-<region>.pooler.supabase.com:5432/postgres?sslmode=require&uselibpqcompat=true
   DIRECT_URL=postgresql://postgres.<ref>:<password>@aws-0-<region>.pooler.supabase.com:5432/postgres?sslmode=require
   ```

   `sslmode=require&uselibpqcompat=true` encrypts the connection with libpq
   semantics. For certificate verification, download the Supabase CA
   (**Database → Settings → SSL Configuration**), provide it to the server (on
   Render as a Secret File, mounted under `/etc/secrets/`) and use
   `?sslmode=verify-full&sslrootcert=/etc/secrets/prod-ca-2021.crt` in `DATABASE_URL`.
   Optionally enable **Enforce SSL** in Supabase.

4. Percent-encode special characters in the password (`@` → `%40`, `#` → `%23`, …).
5. Apply the schema and create the first accounts (from a trusted machine):

   ```bash
   export DATABASE_URL='…' DIRECT_URL='…' JWT_SECRET='…'
   export SEED_ADMIN_USERNAME=admin SEED_ADMIN_PASSWORD='<strong password>'
   npm ci
   npm run db:migrate:deploy
   npm run db:seed
   ```

CPVTS does not use Supabase Auth, Storage or client SDKs — only PostgreSQL.
Moving to another provider means changing the two URLs.

## Render (API)

### Blueprint (recommended)

`render.yaml` defines the `cpvts-api` service:

| Setting      | Value                                            |
| ------------ | ------------------------------------------------ |
| Build        | `npm ci --include=dev && npm run build:api`      |
| Start        | `npm run db:migrate:deploy && npm run start:api` |
| Health check | `/health`                                        |
| Node         | 22                                               |

1. Render → **New → Blueprint** → select the repository.
2. Provide the `sync: false` variables:
   - `DATABASE_URL`, `DIRECT_URL` — from Supabase (above)
   - `FRONTEND_URL` — e.g. `https://cpvts.vercel.app`
   - `CORS_ORIGINS` — comma-separated origins allowed to call the API, e.g.
     `https://cpvts.vercel.app` (add preview or custom domains explicitly)
3. `JWT_SECRET` is generated by Render; `TRUST_PROXY=1` makes client IPs (rate
   limiting, audit logs) correct behind Render's proxy.
4. Deploy and check `https://<service>.onrender.com/health` and `/health/ready`.

### Manual service

Create a **Web Service** from the repository root with the same build/start
commands, health-check path and environment variables.

### Notes

- Free instances sleep when idle; the first request can take up to a minute.
  The web client allows 60 s per request for this reason.
- Migrations run on every start and are no-ops when up to date. Multiple
  instances starting together are safe: Prisma takes an advisory lock.
- Rotating `JWT_SECRET` signs everyone out.
- To seed from Render: **Shell** → `SEED_ADMIN_USERNAME=… SEED_ADMIN_PASSWORD=… npm run db:seed:deploy -w @cpvts/api`.

## Vercel (web)

`vercel.json` at the repository root configures the project:

- install `npm ci`, build `npm run build:web`, output `apps/web/dist`
- SPA rewrite of all paths to `index.html`
- long-term caching for hashed `/assets/*`

Steps:

1. Vercel → **Add New → Project** → import the repository.
   **Root Directory: repository root** (leave empty); framework preset "Other".
2. Environment variables (Production, and Preview if used):
   - `VITE_API_URL=https://<service>.onrender.com`
   - optional `VITE_BRAND_*`, `VITE_DEFAULT_LOCALE`
3. Deploy, then add the Vercel domain to the API's `CORS_ORIGINS`.

`VITE_*` values are compiled into the bundle: changing them requires a
redeploy, and they must never contain secrets.

## Docker

Images are built from the repository root:

```bash
docker build -f apps/api/Dockerfile -t cpvts-api .
docker build -f apps/web/Dockerfile --build-arg VITE_API_URL=https://api.example.com -t cpvts-web .
```

- The API image runs as the unprivileged `node` user, has a `HEALTHCHECK` on
  `/health`, and runs `prisma migrate deploy` before starting.
- The web image is nginx serving the static build with SPA fallback.
- `docker compose --profile app up --build` runs PostgreSQL + API (:4000) +
  web (:8080) locally with development-only credentials.

Any container platform (Fly.io, Railway, Cloud Run, ECS, a VM) can run these images.

## Android WebView (later phase)

The APK will load the deployed web URL. The architecture already supports it:
bearer-token auth (no third-party cookies), responsive layout with a drawer
navigation, self-hosted fonts for Kannada and Devanagari, and long request
timeouts. The WebView must enable JavaScript and DOM storage. Add any custom
origin it uses to `CORS_ORIGINS`.

## Production checklist

- [ ] `NODE_ENV=production`, strong unique `JWT_SECRET` (≥ 32 chars)
- [ ] `CORS_ORIGINS` lists only the real web origins
- [ ] Database URLs use TLS (`sslmode=…`)
- [ ] Migrations applied (`npm run db:migrate:status -w @cpvts/api`)
- [ ] Initial Admin created; seed passwords changed or kept private
- [ ] `/health` and `/health/ready` return 200
- [ ] `VITE_API_URL` points to the production API
- [ ] `VITE_BRAND_SHOW_DEMO_NOTICE=true` unless the institution has authorised an official deployment
